🤔 What is JAX?

JAX is a Python library for accelerator-oriented array computation and program transformation, designed for high-performance numerical computing and large-scale machine learning.

 
JAX started as an research project in Google by a group including key contributors to Autograd and XLA.
Early version of JAX was described in a SysML 2018 paper Compiling machine learning programs via high-level tracing .
Initial (Apache-2.0) open-source release on GitHub was in October 2018.
Since then has seen widespread adoption and developed a large open-source community and downstream ecosystem.

Source: https://docs.jax.dev

✨ Key features

  • 🙌 Ease of use: Offers a NumPy-like API make it accessible to those already familiar with scientific Python ecosystem.
  • 🪄 Transformations: Provides composable function transformations for just-in-time compilation, batching, autodiff and parallelization.
  • 🚀 Acceleration: Allows easily executing the same code on CPUs and accelerator devices such as GPUs and TPUs.

🏗️ API and architecture

JAX’s interface and technology stack consists of

  • • jax package’s public API,
  • • jax package internals and support libraries,
  • • OpenXLA components used for compilation,
  • • multiple supported device backends.

The JAX public API consists of

  • function transforms and array type in the main jax namespace,
  • higher level numerical functions in modules such as jax.numpy, jax.scipy and jax.nn,
  • lower-level numerical primitives mapping to XLA operations in jax.lax module,
  • additional utility and interop modules such as jax.extend, jax.ffi and jax.dlpack.

Below this sits JAX’s internals which include

  • internal implementations of tracing and interpreters and supporting infrastructure in jax._src subpackage,
  • Python wrappers around binary parts of library such as XLA compiler and PJRT runtime in jaxlib,
  • plugin modules for support for device specific libraries such as NVIDIA CUDA and AMD ROCM,

The underlying compiler infrastructure comes from the OpenXLA project consisting of

  • the StableHLO MLIR dialect which JAX uses as its interface to XLA,
  • the XLA compilers themselves which translate the StableHLO operations to executables,
  • PJRT which provides a hardware and framework agnostic interface for compilers and runtimes.

At the bottom of the stack are the actual supported device backends which currently include CPU, TPU and both NVIDIA and AMD GPUs.

🔢 Array API standard

One of main entrypoints to JAX is via jax.numpy module which provides a reimplementation of NumPy API.

import jax.numpy as jnp

def log_sum_exp(x):
    max_x = jnp.max(x)
    return max_x + jnp.log(jnp.sum(jnp.exp(x - max_x)))

JAX v0.4.32+ and NumPy v2.0+ support the Array API standard allowing writing code which works across array backends.

def log_sum_exp(x):
    xp = x.__array_namespace__()
    max_x = xp.max(x)
    return max_x + xp.log(xp.sum(xp.exp(x - max_x)))

👣 Tracing and (JIT) compilation

JAX’s transforms work by tracing a function to determine the operations its performs on inputs of specific shapes and types.
The just-in-time (JIT) compilation transform traces functions to an internal intermediate representation (IR) called a jaxpr .
Each traced numerical primitive then has a lowering rule to transform it to operations in the StableHLO MLIR dialect.
XLA then compiles the StableHLO IR to a device-specific executable which is wrapped as a new Python function.
The wrapped executable is cached under a key depending on argument shapes and types, called and its outputs returned. 
f = lambda x: 2 * x.sum()
jitted_f = jax.jit(f)
x = jax.numpy.arange(7.)
print(f"{f(x)=}\n{jitted_f(x)=}")
f(x)=Array(42., dtype=float32)
jitted_f(x)=Array(42., dtype=float32)

JAX also provides an interface to perform stages individually

traced_f = jitted_f.trace(x)
lowered_f = traced_f.lower()
compiled_f = lowered_f.compile()
traced_f.jaxpr, compiled_f(x)

🇩 Automatic differentiation (AD)

JAX also provides transformations for automatically computing derivatives of a function.

grad_log_sum_exp = jax.grad(log_sum_exp)
hessian_log_sum_exp = jax.hessian(log_sum_exp)
grad_log_sum_exp(x)
Array([0.0015683 , 0.00426308, 0.01158826, 0.03150015, 0.0856263 ,
       0.23275642, 0.6326975 ], dtype=float32)

For a scalar-valued function the gradient can be computed at similar cost to function evaluation.

🔪 Sharp edges

  • Default datatypes and promotion rules tailored for accelerator use - jax_enable_x64 configuration option gives more NumPy like behaviour.
  • Functional programming style - transformed functions should be pure with no side effects.
  • JAX arrays are immutable - indexed updates via at methods, e.g. array = array.at[indices].set(values).
  • JIT compilation requires traced control flow depends only shapes and datatypes of non-static array arguments and that all intermediate and output arrays have static shapes.

📌 Summary

  • If you are already familiar with NumPy, JAX offers an accessible and intuitive route to exploiting (multi-vendor) GPU acceleration and automatic differentiation.
  • Writing numerical code using Array API gives support across NumPy, JAX and other array libraries with minimal effort.
  • Requirement to be able to trace functions to apply (some) JAX transforms puts some constraints on use of control flow.
  • JAX’s functional programming style and structured control primitives can take a bit of getting used to!
